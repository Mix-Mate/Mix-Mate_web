> 모임의 시작부터 마무리까지, MixMate

MixMate는 참가자 모집과 자동 조 편성, 술게임·대화 주제 추천, MVP·2차 참여 투표를 하나의 흐름으로 연결하는 모임 운영 서비스입니다. 운영자는 모임의 진행을 관리하고, 참가자는 자신의 조와 다음 활동을 확인하며 자연스럽게 어울릴 수 있습니다.

## 🎯 About MixMate

여러 사람이 함께하는 모임에서는 참가자 정보를 모으고, 조를 나누고, 다음 일정의 참여 여부를 확인하는 일이 반복됩니다. 운영자는 명단과 진행 상황을 관리해야 하고, 처음 만난 참가자들은 대화를 시작할 계기가 필요합니다.

MixMate는 참여 코드로 참가자를 모으고, 참가자 특성을 고려할 수 있는 조 편성 조건을 제공합니다. 조 편성 이후에는 같은 조의 멤버 확인과 놀이·대화 주제 탐색, MVP 선정과 2차 참여 조사까지 이어지도록 구성했습니다.

모집, 준비, 진행, 투표, 종료 상태에 맞춰 화면과 운영 기능을 연결해 모임의 다음 단계를 안내합니다.

## ✨ Key Features

### 그룹 생성과 참여 코드 기반 참가

- 그룹 이름과 설명, HOST의 그룹 프로필을 입력해 모임을 생성합니다.
- 발급된 참여 코드를 복사해 공유할 수 있습니다.
- 참가자는 6자리 코드를 확인받고 그룹별 프로필을 등록해 참여합니다.
- 홈에서 진행 중인 모임과 완료된 모임을 구분해 확인합니다.

### 참가자 프로필과 명단 관리

- 이름, 소속, 학년, 성별, MBTI, 신입 여부, 직급 등 그룹별 정보를 설정합니다.
- 프로필 공개 여부와 선택 정보인 자기소개·인스타그램 ID를 등록할 수 있습니다.
- 참가자 이름 검색, 일반·운영진 필터, 전체·조별 명단 보기를 제공합니다.
- HOST는 참가자 수동 추가, 차단 및 차단 해제를 관리하고 참가자 구성 통계를 확인합니다.

### 조건을 선택하는 자동 조 편성

- 조 개수와 성별 균형, MBTI 균형, 학년 분산, 신입 여부 분산, 직급 분산 조건을 설정합니다.
- 1차 편성에서는 특정 참가자를 원하는 조에 고정할 수 있습니다.
- 서버에서 반환한 편성 결과와 경고를 확인하고, 재셔플하거나 결과를 확정합니다.
- 2차에는 참여 인원을 확인한 뒤 새로운 조 편성을 진행합니다.

### 내 조와 같은 조 멤버 확인

- 현재 회차에 배정된 조 번호와 같은 조 참가자를 확인합니다.
- 공개된 참가자 프로필을 열어 서로의 정보를 살펴볼 수 있습니다.
- 이전 조 기록 화면에서 1차에 함께했던 조와 멤버를 확인합니다.

### 술게임과 대화 주제 추천

- 술게임의 구성과 진행 방법을 확인하고 다른 게임으로 넘겨볼 수 있습니다.
- 학교생활, 취미, 여행, 음식 등 카테고리별 스몰토크 주제를 제공합니다.
- 두 가지 선택지를 제시하는 밸런스 게임 주제를 함께 살펴볼 수 있습니다.

### MVP · 2차 참여 투표

- 자신을 제외한 1차 같은 조 멤버 중 MVP를 선택합니다.
- MVP 투표에 이어 2차 참여 또는 불참 의사를 제출합니다.
- 2차 참여·불참·미투표 현황과 투표 완료 인원을 확인합니다.
- HOST는 수동 등록 참가자의 2차 참여 의사를 대신 입력하거나 정정하고, 전체 투표를 마감할 수 있습니다.
- 결과 화면에서 우리 조 MVP 공개 연출과 전체 MVP 결과를 확인합니다.

### HOST의 모임 진행 관리

- 참가자 모집 마감, 조 편성 확정, 1차 종료와 투표 시작을 관리합니다.
- 투표 마감 후 2차 진행 여부를 결정합니다.
- 2차를 진행하면 조 편성을 다시 확정하고, 모임 종료까지 관리합니다.

## 🔄 User Flow

### HOST Flow

로그인 후 그룹 정보와 HOST 프로필을 등록하면 참여 코드가 발급됩니다.

```text
참가자 모집 [RECRUITING]
    │ 참여 코드 공유 · 참가자 확인
    ↓ HOST가 모집 마감
1차 준비 [BEFORE_FIRST_ROUND]
    │ 편성 조건 설정 · 고정 멤버 지정 · 결과 확인
    ↓ 조 편성 확정
1차 진행 [FIRST_ROUND]
    │ 내 조 확인 · 놀이와 대화 주제 이용
    ↓ HOST가 1차 종료
MVP · 2차 참여 투표 [VOTING]
    │ 투표 현황 확인 · 수동 등록 참가자 응답 관리
    ↓ 투표 마감
투표 종료 [VOTE_CLOSED]
    ├─ 모임 종료 선택 → 모임 종료 [FINISHED]
    │
    └─ 2차 진행 선택
           ↓
       2차 준비 [BEFORE_SECOND_ROUND]
           │ 참여 인원 확인 · 조 재편성
           ↓ 조 편성 확정
       2차 진행 [SECOND_ROUND]
           ↓ HOST가 2차 종료
       모임 종료 [FINISHED]
```

### Participant Flow

```text
로그인
  → 참여 코드 입력 및 검증
  → 그룹별 프로필 등록
  → 모집·조 편성 대기
  → 내 조와 같은 조 멤버 확인
  → 술게임·스몰토크·밸런스 게임 주제 이용
  → MVP 투표
  → 2차 참여 여부 투표
  → 투표 현황 및 결과 확인
```

2차 참여자는 HOST의 진행 결정과 조 편성을 기다린 뒤 새 조를 확인합니다. 2차 불참자는 진행 중인 모임의 대기 안내를 받으며, 모임 종료 후 완료된 모임에서 종료 화면을 확인할 수 있습니다.

화면에 표시되는 진행 상태는 서버의 그룹 `status`를 바탕으로 구성합니다. 관리자 화면은 그룹 상세 응답의 `myRole`을 확인해 접근을 제어합니다.

## 💡 Technical Highlights

### 1. 그룹 상태에 따른 화면과 액션 제어

**문제**  
동일한 그룹이라도 모집·준비·진행·투표 단계에 따라 보여줄 화면과 가능한 행동이 달라집니다.

**해결**  
8개의 `GroupStatus`를 정의하고 상태 이름, 회차, 홈 화면 시나리오와 권한 정보를 매핑했습니다. 모집 마감, 조 편성 확정, 2차 진행 결정 등 주요 변경 뒤에는 그룹 정보를 다시 조회해 화면에 반영합니다.

**결과**  
서버 상태에 맞춰 대기 화면, 진행 메뉴, 투표 화면과 종료 화면을 구성합니다.

### 2. 그룹 역할 기반 관리자 화면 접근 제어

**문제**  
HOST와 일반 참가자가 같은 그룹을 이용하면서도 운영 기능에 대한 접근은 구분해야 합니다.

**해결**  
그룹 레이아웃에서 상세 정보를 Context로 공유하고, 관리자 레이아웃의 `AdminAccessGuard`가 `myRole === "HOST"`일 때만 하위 화면을 표시합니다. 프로필의 직급인 `STAFF/MEMBER`는 그룹 역할인 `HOST/PARTICIPANT`와 별도로 정의했습니다.

**결과**  
관리자 화면의 진입 검사와 공용 화면의 운영 버튼 표시를 그룹 역할에 연결합니다.

### 3. SSE와 REST 응답 사이의 상태 일관성 유지

**문제**  
그룹 상태 변경을 여러 화면에 반영해야 하며, 늦게 도착한 REST 응답이 더 최근의 SSE 상태를 덮어쓸 수 있습니다.

**해결**  
그룹 레이아웃에서 SSE 연결을 공유하고, 이벤트의 형식과 그룹 ID를 검증합니다. REST 요청 도중 새 상태 이벤트를 받았다면 해당 상태를 보존하고, 요청 식별자로 이전 요청의 응답을 구분합니다. 재연결에는 최대 30초 간격의 지수 백오프를 적용합니다.

모집 화면의 인원수, 모집 중인 관리자 참가자 목록과 투표 현황은 별도의 약 3초 간격 폴링으로 갱신합니다.

**결과**  
그룹 진행 상태와 명단·투표 현황을 각각의 갱신 방식으로 반영하고, 응답 도착 순서로 인한 상태 역전을 방지합니다.

### 4. 투표 흐름의 Navigation / History 관리

**문제**  
투표 중 뒤로가기, URL 직접 접근, 늦은 제출 응답이 현재 단계와 맞지 않는 화면 이동을 유발할 수 있습니다.

**해결**  
실제 브라우저 히스토리에 위치 정보를 덧붙여 뒤로가기 방향을 판별합니다. `useVoteNavigation`은 해당 흐름의 목적지로 이동하고 중복 이동을 제한합니다. MVP·2차 참여 화면에서는 그룹 상태와 제출 여부를 확인해 이동할 화면을 결정합니다.

**결과**  
투표 흐름에 필요한 복귀 경로를 제어하면서, 판별 가능한 앞으로가기와 불명확한 히스토리 이동은 브라우저 기본 동작을 유지합니다.

### 5. 조 편성 입력과 서버 요청 모델의 분리

**문제**  
화면에서 선택한 회차·편성 조건·고정 멤버를 서버가 요구하는 요청 형식으로 전달하고, 여러 편성 화면 사이에서 결과를 공유해야 합니다.

**해결**  
Mapper에서 회차와 조건 키를 API 형식으로 변환합니다. 설정과 임시 결과는 그룹 ID·회차별 메모리 `Map`에 저장합니다. 1차 고정 멤버 지정, 서버 경고 확인, 재셔플, 최종 확정을 각각의 단계로 구성했습니다.

**결과**  
입력 설정부터 결과 확인·확정까지 연결하며, 2차 편성은 1차 조 전체를 고정 멤버로 넘기지 않고 새로 요청합니다.

### 6. 투표 중복 제출과 결과 반영 지연 처리

**문제**  
연속 클릭, 이미 제출한 투표의 재시도, 투표 종료 직후의 결과 조회 지연을 처리해야 합니다.

**해결**  
투표 Hook에서 제출 상태와 `ref`를 함께 확인해 진행 중인 요청을 제한합니다. 이미 투표했다는 서버 오류는 별도로 구분해 다음 화면으로 연결합니다. 결과 조회의 `409 / INVALID_GROUP_STATUS` 응답에는 1.5초 간격으로 최대 10회 재시도합니다.

**결과**  
정상 제출과 이미 제출된 상태를 구분하고, 서버 상태 반영 지연에 대응하는 결과 조회 흐름을 제공합니다.

### 7. 오류 상황에 맞춘 사용자 피드백

**문제**  
입력 오류, 인증 만료, 그룹 접근 거부, 네트워크 실패는 사용자가 취해야 할 다음 행동이 서로 다릅니다.

**해결**  
API별 오류 객체에 HTTP 상태·오류 코드·필드 오류를 담고, 공통 Mutation Hook에서 요청 중 상태와 오류 메시지를 관리합니다. 화면에서는 필드별 안내, 토스트, 다이얼로그와 재시도 UI를 사용합니다. SSE 인증 만료 시에는 인증 정보를 정리하고 로그인 화면으로 이동합니다.

**결과**  
오류 원인에 따라 입력 수정, 재시도, 로그인 또는 홈 이동을 안내합니다.

```text
│   │   ├── auth/               # 인증과 이메일 확인
│   │   ├── group/              # 그룹 정보·상태·SSE
│   │   ├── participant/        # 참가자 명단·관리·통계
│   │   ├── profile/            # 그룹별 프로필
│   │   ├── blacklist/          # 참가자 차단·해제
│   │   ├── assignment/         # 조 편성 설정·요청·임시 결과
│   │   ├── team/               # 내 조와 조원 조회
│   │   ├── history/            # 이전 1차 조 기록
│   │   ├── play/               # 게임·대화 주제 데이터
│   │   ├── session/            # 모임 화면 상태와 접근 제어
│   │   └── vote/               # MVP·2차 참여 투표와 결과
│   ├── modals/                 # 관리자·참가자 다이얼로그
│   └── shared/
│       ├── api/                # API 기본 주소와 인증 토큰 유틸리티
│       ├── assets/             # 공통 화면 이미지
│       ├── hooks/              # Mutation·Toast 공통 Hook
│       ├── lib/navigation/     # 라우트·쿼리·히스토리 유틸리티
│       ├── types/              # 공통 타입
│       └── ui/                 # 공통 UI와 스타일 토큰
├── .github/workflows/ci.yml    # lint·test·build
├── next.config.ts
├── vitest.config.ts
└── vercel.json
```

라우트 연결은 `app`, 화면 조합은 `screens`, 기능별 로직은 `features`에 배치합니다. 공통 UI와 유틸리티는 `shared`에서 재사용하며, 테스트는 관련 소스 가까이에 배치합니다.

## 🗺 Routes

`[groupId]`는 그룹 ID이며, 조 편성 경로의 `[round]`에는 `1` 또는 `2`를 사용합니다.

| Route | 설명 |
| --- | --- |
| `/login`, `/signup` | 로그인과 이메일 인증 기반 회원가입 |
| `/home` | 진행 중·완료된 모임 목록 |
| `/groups/create`, `/groups/create/extra` | 그룹 정보와 HOST 프로필 입력 |
| `/groups/join`, `/groups/[groupId]/extra` | 참여 코드 확인과 참가자 프로필 등록 |
| `/groups/[groupId]` | 역할·진행 상태에 따른 그룹 홈 |
| `/groups/[groupId]/participants` | 참가자 명단과 조별 보기 |
| `/groups/[groupId]/team` | 내 조와 같은 조 멤버 확인 |
| `/groups/[groupId]/play` | 술게임·스몰토크·밸런스 게임 메뉴 |
| `/groups/[groupId]/votes/mvp`, `/groups/[groupId]/votes/attendance` | MVP와 2차 참여 투표 |
| `/groups/[groupId]/votes/status`, `/groups/[groupId]/votes/result` | 투표 현황과 결과 |
| `/groups/[groupId]/admin/recruitment` | 참여 코드 공유와 모집 관리 |
| `/groups/[groupId]/admin/assignments/[round]/setup` | 회차별 조 편성 설정 |
| `/groups/[groupId]/admin/progress` | 모임 진행 현황과 회차 종료 |
| `/groups/[groupId]/completed` | 모임 종료 화면 |

## 🚀 Getting Started

### 실행 환경

- Node.js 24.x
- npm
- 인증·그룹·조 편성·투표 API를 제공하는 백엔드 서버

### 의존성 설치

`package.json`이 있는 `mix-mate-web` 디렉터리에서 실행합니다.

```bash
npm ci
```

### 환경변수

프로젝트 루트의 `.env.local`에 연결할 백엔드의 기본 주소를 설정합니다.

```env
NEXT_PUBLIC_API_BASE_URL=
```

빈 값 대신 사용할 백엔드 주소를 입력해야 합니다. 인증 토큰이나 비밀 값은 이 항목에 넣지 않습니다.

### 개발 서버

```bash
npm run dev
```

### 빌드 및 실행

```bash
npm run build
npm run start
```

### 정적 검사 및 테스트

```bash
npm run lint
npm run test
```

GitHub Actions는 `main`, `dev` 브랜치의 Push와 Pull Request에서 의존성 설치, lint, test, build를 실행하도록 구성되어 있습니다.
