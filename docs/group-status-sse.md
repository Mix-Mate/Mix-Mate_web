# 그룹 진행 상태 SSE

그룹 공통 Provider에서 `GET /api/v1/groups/{groupId}/status/stream`을 구독한다.
그룹 상세 REST 조회는 초기 데이터와 명시적 재조회에 사용하고, 공통 2초 폴링은 제거했다.

## 연결과 상태 반영

- `@microsoft/fetch-event-source`로 Bearer 헤더를 전달한다. 토큰을 URL에 넣지 않는다.
- `status` 이벤트의 `{ groupId, status }`를 검사해 현재 그룹의 상태만 반영한다.
- 최초 연결 및 재연결의 snapshot도 같은 이벤트로 처리한다. 이벤트 이력 재생은 사용하지 않는다.
- `:ping` 주석, 다른 이벤트 이름, 잘못된 JSON/상태 및 다른 그룹의 이벤트는 무시한다.
- 모집·조 편성 대기·투표 화면을 포함해 그룹 레이아웃 내에서 연결 하나를 유지한다.
- 탭이 백그라운드로 가도 연결을 유지한다. 그룹 변경, 추가 정보 입력 화면 진입, 언마운트, 로그아웃 시 해제한다.
- 같은 탭과 다른 탭의 토큰 변경을 감지하며, 재연결 요청마다 최신 토큰을 읽는다.
- REST 요청 도중 SSE를 받으면 그 응답의 상태 필드는 최신 SSE 상태로 병합한다. 다른 상세 필드와 재조회 반환값도 유지한다.
- 상태 구독과 화면 이동은 분리한다. 투표 흐름에서는 구독을 유지하면서 중복 이동을 막는다. 투표 시작 및 그룹 재진입 시 관리자(HOST)를 포함한 모든 참가자는 MVP 투표 화면으로 이동한다. 투표 완료 여부에 따른 후속 이동은 투표 화면에서 처리하며, 관리자의 투표 완료 후 관리자 투표 현황으로 이동하는 기존 흐름은 유지한다.

## 종료 및 오류

- 서버의 30분 정상 종료(EOF)도 재연결한다.
- 네트워크 오류, 5xx, 408, 429는 1초부터 최대 30초 간격으로 재시도하며 약간의 무작위 지연을 더한다. 유효한 snapshot을 받으면 지연을 초기화한다.
- 401은 인증 정보를 지우고 로그인 안내를 표시한다. 토큰 재발급 API는 이번 명세에 없으므로 자동 재발급을 추가하지 않았다.
- 403·404 및 기타 재시도 불가능한 응답은 자동 재시도를 중단하고 그룹 오류 화면을 표시한다. 사용자가 다시 시도하면 REST 권한 확인 후 재구독한다.
- 일시적인 연결 오류 동안에는 마지막 상태를 유지한다. 주기적인 REST 폴링으로 전환하지 않는다.

## 유지한 조회

이 스트림은 그룹 상태만 전송한다. 관리자 모집 화면의 참가자 수 조회,
참가자 목록 및 투표 현황의 기존 3초 폴링은 유지한다.
조 편성 화면의 로컬 진행률 타이머도 변경하지 않는다.

## 검증

- `npm test`: SSE 청크 파싱, 모든 상태 값, 재연결, 인증 오류, 연결 정리,
  대기 화면과 내 조 갱신, 투표 종료 이동, REST/SSE 경합을 포함한 회귀 테스트.
- 로컬 가상 API와 실제 브라우저: 모집 → 1차 준비 → 진행 → 투표 → 투표 종료,
  연결 종료 후 2차 준비 snapshot 복구, 2차 진행 및 재연결 401 처리를 확인했다.
- 실제 백엔드 배포에서 추가 확인할 항목: CORS와 Authorization 사전 요청,
  프록시 버퍼링·timeout, 커밋 이후 발행, 최초 snapshot과 구독 등록 사이 변경 누락 방지,
  서버가 여러 인스턴스인 경우 이벤트 전달.
- 백엔드 정책상 인증은 연결 시 한 번만 수행된다. 연결 중 토큰 만료나 권한 변경은
  최대 30분 뒤 재연결 시 반영되며, 클라이언트가 원격 권한 변경을 즉시 감지하지는 못한다.
